# Rule reference

Generated by `python -m roschema.rules.gendocs`; do not edit by hand.


## Breaking-change rules (`check`)

### RS001 -- Field removed

A field was removed from an interface section.

- Levels: wire, source, introspection
- Default severity: error

*Rationale:* CDR is positional, so removing a field shifts every following field and breaks the wire layout, the generated API and name-based tooling.

```
# before
int32 a
int32 b
# after
int32 a
```

### RS002 -- Field added

A field was added to an interface section.

- Levels: wire, source
- Default severity: error

*Rationale:* Appending a field is source-compatible but still changes the CDR wire layout, so a new publisher and an old subscriber cannot interoperate.

```
# before
int32 a
# after
int32 a
int32 b
```

### RS003 -- Field type changed

A field kept its name but changed type (including fixed-array size).

- Levels: wire, source
- Default severity: error

*Rationale:* A different type serialises to different bytes and changes the generated API. A fixed array's size is part of its type and wire layout.

```
# before
float32 theta
# after
float64 theta
```

### RS004 -- Fields reordered

Fields that exist on both sides appear in a different order.

- Levels: wire
- Default severity: error

*Rationale:* CDR encodes fields by position, so reordering silently corrupts the wire stream.

```
# before
int32 a
int32 b
# after
int32 b
int32 a
```

### RS005 -- Field renamed

A field at the same position kept its type but changed name.

- Levels: source, introspection
- Default severity: error

*Rationale:* The wire bytes are unchanged, but generated field accessors and every name-based tool (bags, echo, YAML config) break.

```
# before
float32 theta
# after
float32 yaw
```

### RS006 -- Array kind changed

A field changed between fixed, bounded and unbounded array forms.

- Levels: wire, source
- Default severity: error

*Rationale:* Fixed, bounded and unbounded arrays use different CDR encodings and generate different container types.

```
# before
int32[] data
# after
int32[8] data
```

### RS007 -- Bound tightened

A bounded array or string had its capacity reduced.

- Levels: wire
- Default severity: error

*Rationale:* A message that was valid before may now exceed the new bound, so a stricter subscriber rejects previously-valid data.

```
# before
string<=64 name
# after
string<=16 name
```

### RS008 -- Bound loosened

A bounded array or string had its capacity increased.

- Levels: wire
- Default severity: warn

*Rationale:* Newer messages may exceed the old bound, so an older subscriber can reject them; the reverse direction stays compatible, hence a warning.

```
# before
string<=16 name
# after
string<=64 name
```

### RS020 -- Constant removed

A named constant was removed from an interface.

- Levels: source
- Default severity: error

*Rationale:* Code referencing the constant fails to compile; the wire format is unaffected.

```
# before
int32 MODE_A=0
int32 MODE_B=1
# after
int32 MODE_A=0
```

### RS021 -- Constant value changed

A constant kept its type but changed value.

- Levels: source, behavior
- Default severity: error

*Rationale:* Callers compiled against the old value silently disagree with new ones, and the meaning of already-recorded data shifts.

```
# before
int32 TIMEOUT=30
# after
int32 TIMEOUT=60
```

### RS022 -- Constant type changed

A constant kept its name but changed type.

- Levels: source
- Default severity: error

*Rationale:* The generated constant's type changes, breaking code that used the old type.

```
# before
int32 LIMIT=100
# after
float32 LIMIT=100.0
```

### RS030 -- Field default changed

A field's default value was added, removed or changed.

- Levels: behavior
- Default severity: warn

*Rationale:* The wire format and API are unchanged, but unset fields deserialise to a different value, altering behaviour.

```
# before
int32 timeout 30
# after
int32 timeout 60
```

### RS040 -- Interface removed

A whole .msg/.srv/.action definition no longer exists.

- Levels: wire, source, introspection, behavior
- Default severity: error

*Rationale:* Every publisher, subscriber and downstream package that referenced it breaks.

```
# before
my_msgs/msg/State.msg present
# after
my_msgs/msg/State.msg deleted
```

### RS060 -- MESSAGE_VERSION not bumped

A structural change was made to an interface that defines a MESSAGE_VERSION constant, but the constant was not increased.

- Levels: behavior
- Default severity: off

*Rationale:* Projects following the PX4 MESSAGE_VERSION convention rely on the constant tracking every structural change for runtime translation.

```
# before
uint32 MESSAGE_VERSION=1
int32 a
# after
uint32 MESSAGE_VERSION=1
int32 a
int32 b
```

### RS110 -- Transitively broken by an embedded type

An interface embeds (directly or through nested types) another interface whose wire layout changed, so it is broken even though its own definition did not change. Reported only with --deep.

- Levels: wire
- Default severity: error

*Rationale:* CDR inlines nested messages, so a wire-breaking change to an embedded type breaks every interface that contains it.

```
# before
geometry_msgs/Point position  # Point unchanged here
# after
geometry_msgs/Point position  # but Point.x changed type
```


## Lint rules (`lint`)

### RSL001 -- Field name not snake_case

Field names must be lowercase snake_case, matching rosidl.

- Default severity: error

*Rationale:* rosidl requires field names to be lowercase with single underscores and no leading digit or trailing underscore; other forms fail generation.

### RSL002 -- Constant name not UPPER_SNAKE_CASE

Constant names must be uppercase with underscores, matching rosidl.

- Default severity: error

*Rationale:* rosidl requires constant names to be uppercase; other forms fail generation.

### RSL003 -- Interface name not PascalCase

Message/service/action file names must be PascalCase, matching rosidl.

- Default severity: error

*Rationale:* rosidl requires message type names to start with a capital and be alphanumeric.

### RSL004 -- Field missing documentation

A field has no trailing documentation comment.

- Default severity: off

*Rationale:* Documented fields are easier to consume. Off by default; only trailing comments are tracked (preceding comments are not retained in the IR).

### RSL005 -- Discouraged type

Uses `char`, or a scalar `byte`, both deprecated aliases in ROS 2.

- Default severity: warn

*Rationale:* ROS 2 deprecated `char` and `byte` as scalar types in favour of `uint8`/`int8`; `byte[]` remains idiomatic for opaque binary data.

### RSL006 -- Unbounded string or array

A field is an unbounded array or unbounded string.

- Default severity: off

*Rationale:* Unbounded fields allocate dynamically, which real-time users often avoid. Off by default; informational.

### RSL010 -- Request/response field shadowing

A field name is used in both the request and response of a service.

- Default severity: warn

*Rationale:* Reusing a name across request and response is a common source of confusion.
